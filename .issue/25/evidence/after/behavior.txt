# 동작 실증 — CI 인프라 원소 (.github/workflows/ci.yml)

## ts-check 잡 (python-check 직후, 9 스텝)
  checkout@v4 → setup-node@v4(node 22) → apt(bison flex libsqlite3-dev)
  → make extension → mkdir+cp build/graphqlite.so → npm ci → tsc --noEmit → eslint . → npm test

## needs 배열 6곳 전부 ts-check 편입 (게이트 실제 작동)
  full-build-unix / full-rust-tests / full-python-tests-linux /
  full-python-tests-macos / full-windows-tests / performance-tests

## Node 하한 확정
  engines.node: >=22.5.0 (F-01 잠정) → >=22.13.0
  근거: node:sqlite는 22.5.0 도입, loadExtension/allowExtension은 22.x LTS(22.13.0)로 백포트(문서).
  로컬은 v24.13.0만 가용 → 22.x 직접 실측 불가. ts-check CI 잡이 node 22에서 실제 게이트로 검증.

## ts-check 스텝을 로컬에서 실증 (CI가 GitHub에서 하는 것과 동일 명령)
  npm ci        → OK (lockfile 동기화)
  npx tsc --noEmit → 무오류
  npx eslint .  → 통과 (No issues) — eslint.config.js(typescript-eslint recommended) 신규
  npm test (node --test) → 200/200

## eslint 도입 부수 변경 (npx eslint . 스텝이 실제 통과하도록)
  - eslint.config.js 신규 (flat, typescript-eslint recommended, dist/node_modules/npm 무시)
  - package.json devDeps: eslint ^9, typescript-eslint ^8 + lint 스크립트, package-lock.json 갱신
  - src/manager.ts: 빈 인터페이스 GraphManagerOptions → type alias (no-empty-object-type 1건 해소)
